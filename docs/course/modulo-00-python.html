Módulo 00: Cómo se escribe un modelo para GSUA-CSB (Python)¶

Curso guiado de GSUA-CSB

Todo el curso (muestreo, incertidumbre, sensibilidad, estimación) trabaja sobre un modelo de usuario: una función de Python que tú escribes. El paquete gsua_csb no ve tus ecuaciones; solo llama a esa función con un vector de factores y lee lo que devuelve. Este módulo enseña ese contrato paso a paso, en espejo con la versión MATLAB:

  1. la firma func(pars, domain, **opt), UserFunctionModel y la forma de la salida;
  2. el orden de los factores: primero los parámetros, después las condiciones iniciales;
  3. un modelo discreto (un bucle) y uno continuo (solve_ivp evaluado en la rejilla);
  4. cómo se declaran range, names y output_names, qué hace el objeto model (la tabla T de MATLAB) y cómo se evalúa con model.evaluate (el gsua_eval de MATLAB);
  5. los errores típicos (firma, orientación, rejilla, unidades);
  6. un ejercicio: programar un SIR discreto desde cero.

1. El contrato de un modelo de usuario¶

def mi_modelo(pars, domain, **opt) -> np.ndarray:   # forma (n_salidas, len(domain))

Entradas

  • pars: arreglo con los factores. La posición manda: pars[0] es el factor de la fila 0 de range, pars[1] el de la fila 1, etc. Convención del curso: primero los parámetros, después las condiciones iniciales.
  • domain: la rejilla de puntos donde quieres la salida (no [t0, tf] como en MATLAB). Es model.domain por defecto, o el xdata que pases a model.evaluate(pars, xdata).
  • **opt: lo que pongas en UserFunctionModel(..., opt={...}) llega como argumentos con nombre. Si no usas opt, basta con func(pars, domain).

Salida: un arreglo de NumPy de forma (n_salidas, len(domain)): una fila por salida, en el orden de output_names, evaluada exactamente en los puntos de domain. Con una sola salida también vale un vector (len(domain),).

Diferencia clave con MATLAB. En MATLAB el modelo devuelve sol.x/sol.y y gsua_eval interpola. En Python nadie interpola por ti: la función recibe la rejilla y debe devolver los valores en esos puntos. Y como domain puede empezar en cualquier punto, el modelo tiene que saber por su cuenta en qué tiempo t0 vale la condición inicial.

2. Paso 1 — un modelo discreto: la logística¶

$N(t+1) = N(t) + r\,N(t)\,(1 - N(t)/K)$, con tres factores: r, K (parámetros) y N0 (condición inicial). El bucle avanza un paso por iteración desde t0 hasta el último punto pedido; al final se devuelven los valores en los puntos de domain.

In [3]:
def logistica_discreta(pars, domain, t0=0):
    """N(t+1) = N(t) + r*N(t)*(1 - N(t)/K).  pars = [r, K, N0]; N(t0) = N0."""
    r, K, N0 = pars                                   # parámetros primero, condición inicial al final
    domain = np.asarray(domain, dtype=float)

    pasos = np.arange(t0, int(np.ceil(domain.max())) + 1)   # t0, t0+1, ..., último paso pedido
    N = np.zeros(len(pasos))
    N[0] = N0
    for k in range(len(pasos) - 1):
        N[k + 1] = N[k] + r * N[k] * (1 - N[k] / K)

    return np.interp(domain, pasos, N)               # (len(domain),): una sola salida

Antes de dárselo al paquete, llámalo tú a mano y mira la forma:

3. Paso 2 — declararlo con UserFunctionModel: range, names y output_names¶

range es una matriz (Np, 2) con [mínimo, máximo] por fila. La fila i corresponde a pars[i] y a names[i]: las tres listas van en el mismo orden. output_names nombra las filas de la salida, también en orden. domain es la rejilla por defecto.

El objeto model hace el papel de la tabla T de MATLAB: guarda nombres, rangos, nominal (por defecto, el punto medio), rejilla y salidas. Todas las funciones del curso (design_matrix, uncertainty_analysis, sensitivity_analysis, parameter_estimation...) leen el modelo desde aquí.

4. Paso 3 — evaluar con model.evaluate y model.evaluate_batch¶

model.evaluate(pars, xdata) hace una simulación (pars con los Np factores); xdata es opcional y por defecto es model.domain. model.evaluate_batch(M) hace una por fila de M (forma (N, Np), como la que devuelve design_matrix).

Ojo con el espejo: en MATLAB par es Np x N (una columna por simulación) y la salida de gsua_eval es N x tiempo x salidas; en Python M es N x Np (una fila por simulación) y la salida de evaluate_batch es N x salidas x tiempo.

5. Paso 4 — un modelo continuo: el SIR con solve_ivp¶

Un modelo continuo resuelve sus EDO dentro de la función. El patrón es:

  1. integrar con solve_ivp desde t0 (donde vale la condición inicial) hasta el último punto pedido;
  2. pedirle la solución exactamente en la rejilla con t_eval=domain;
  3. devolver sol.y, que ya viene como (estados, tiempo).

Factores: beta, gamma (parámetros), S0, I0 (condiciones iniciales). Salidas: S, I y R, en ese orden de filas.

In [8]:
def sir_continuo(pars, domain, t0=0.0):
    """SIR continuo. pars = [beta, gamma, S0, I0]; R(t0) = 0. Salida (3, len(domain)) = [S; I; R]."""
    beta, gamma, S0, I0 = pars
    domain = np.asarray(domain, dtype=float)

    def rhs(t, y):
        S, I, R = y
        return [-beta * S * I, beta * S * I - gamma * I, gamma * I]

    sol = solve_ivp(rhs, (t0, domain.max()), [S0, I0, 0.0],
                    t_eval=domain, rtol=1e-6, atol=1e-8)
    return sol.y                                       # (3, len(domain))

6. Fijar un factor: rango degenerado¶

Si un factor no te interesa, dale un rango con mínimo = máximo (o usa model.fix). Queda fuera del muestreo y la estimación. A diferencia de MATLAB, donde el factor fijo desaparece de T y par lleva solo los libres, en Python pars siempre lleva los Np factores: design_matrix devuelve todas las columnas y mantiene la del factor fijo constante.

7. Errores típicos¶

(a) Firma: opt sin argumento que lo reciba. Si das opt={"t0": 0} pero la función es func(pars, domain), Python se queja del argumento inesperado. Declara t0=... o **opt.

In [13]:
def logistica_sin_opt(pars, domain):
    return logistica_discreta(pars, domain)

m_mal = UserFunctionModel(func=logistica_sin_opt, names=["r", "K", "N0"], range=rangos_log,
                          domain=np.arange(0, 51), opt={"t0": 0})
try:
    m_mal.evaluate(m_mal.nominal)
except TypeError as e:
    print("TypeError:", e)

TypeError: logistica_sin_opt() got an unexpected keyword argument 't0'

(b) output_names no coincide con las filas. output_names no reordena nada: solo pone nombre a las filas, en orden. Si declaras una única salida "I" para un modelo cuya fila 0 es S, set_output("I") te entrega S con la etiqueta "I", sin ningún error.

(c) Orientación. Si devuelves sol.y.T (tiempo, salidas), Python no lo corrige: set_output selecciona filas y te entrega un instante de tiempo en lugar de una salida.

(d) Rejilla: la condición inicial no vive en domain[0]. Un error frecuente es integrar con t_span=(domain[0], domain[-1]). Funciona mientras la rejilla empiece en 0, pero si pides xdata desde el día 20 la epidemia "arranca" el día 20 con I0 infectados.

def sir_arranca_en_domain0(pars, domain):
    beta, gamma, S0, I0 = pars
    rhs = lambda t, y: [-beta * y[0] * y[1], beta * y[0] * y[1] - gamma * y[1], gamma * y[1]]
    return solve_ivp(rhs, (domain[0], domain[-1]), [S0, I0, 0.0], t_eval=domain,
                     rtol=1e-6, atol=1e-8).y      # MAL: t0 = domain[0]

(f) Unidades. Rangos, condiciones iniciales y rejilla deben estar en las mismas unidades. En sir_continuo, beta va en 1/(persona·día) porque el término es beta*S*I con S e I en personas. Si escribes S0 e I0 como fracciones de la población sin cambiar beta, el número reproductivo $R_0 = \beta S_0/\gamma$ se hunde; si la rejilla está en semanas y gamma en 1/día, el tiempo de recuperación queda multiplicado por 7.

9. Ejercicio: programa un SIR discreto desde cero¶

Con un paso de un día, el SIR discreto es

$$S_{t+1} = S_t - \beta S_t I_t,\quad I_{t+1} = I_t + \beta S_t I_t - \gamma I_t,\quad R_{t+1} = R_t + \gamma I_t.$$

  1. Copia sir_discreto_plantilla.py como mi_sir_discreto.py.
  2. Completa el TODO del bucle con las tres ecuaciones.
  3. Pásalo por verificar_modelo con output_names = ["S", "I", "R"].
  4. Envuélvelo en UserFunctionModel con los mismos range, names y output_names que sir_continuo y la rejilla np.arange(0, 81).
  5. Evalúa el nominal y grafica I(t) junto a la de sir_continuo.

Preguntas. ¿Por qué no coinciden las dos curvas de I aunque las ecuaciones "son las mismas"? ¿Qué pasa con S si beta*S0 > 1? ¿Se conserva S + I + R en tu modelo?

La plantilla (ya cumple el contrato; solo le falta la dinámica):

"""
sir_discreto_plantilla.py — ejercicio del módulo 0: un SIR en tiempo discreto.

Copia este archivo como mi_sir_discreto.py y completa el TODO.

Con un paso de un día, el SIR discreto es:
    S(t+1) = S(t) - beta*S(t)*I(t)
    I(t+1) = I(t) + beta*S(t)*I(t) - gamma*I(t)
    R(t+1) = R(t) + gamma*I(t)

Factores (primero parámetros, después condiciones iniciales):
    pars[0] -> beta  (1/(persona*día))
    pars[1] -> gamma (1/día)
    pars[2] -> S0    (personas)
    pars[3] -> I0    (personas)
R0 = 0 al inicio, en el día t0.

Salida: arreglo (3, len(domain)) = [S; I; R] en los días de domain.
"""
import numpy as np


def sir_discreto_plantilla(pars, domain, t0=0):
    beta, gamma, S0, I0 = pars
    domain = np.asarray(domain, dtype=float)

    dias = np.arange(t0, int(np.ceil(domain.max())) + 1)   # t0, t0+1, ..., último día pedido
    Y = np.zeros((3, len(dias)))                            # 3 salidas -> 3 filas
    Y[:, 0] = [S0, I0, 0.0]

    for k in range(len(dias) - 1):
        S, I, R = Y[:, k]
        # TODO: escribe aquí las tres ecuaciones de actualización.
        #       Mientras tanto la plantilla deja S, I y R constantes.
        Y[:, k + 1] = [S, I, R]

    # Devolver exactamente los puntos pedidos (interpolación lineal entre días)
    return np.vstack([np.interp(domain, dias, fila) for fila in Y])

10. Resumen: lista de chequeo¶

  • func(pars, domain, **opt) devuelve un arreglo (n_salidas, len(domain)), evaluado en los puntos de domain.
  • pars[i] = fila i de range = names[i]: parámetros primero, condiciones iniciales después.
  • La condición inicial vale en un t0 fijo que el modelo conoce (argumento t0 u opt), no en domain[0].
  • Discreto: un bucle de t0 al último punto pedido. Continuo: solve_ivp(..., t_eval=domain).
  • UserFunctionModel(func, names, range, domain, output_names, opt=...) es la tabla T de MATLAB.
  • model.evaluate(pars) → (salidas, tiempo); model.evaluate_batch(M) con M de N x Np → (N, salidas, tiempo).
  • Una sola salida: model.set_output("I"). Un factor fijo: rango [v, v] o model.fix("I0").
