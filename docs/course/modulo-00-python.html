Módulo 00: Cómo se escribe un modelo para GSUA-CSB (Python)¶

Curso guiado de GSUA-CSB

Todo el curso (muestreo, incertidumbre, sensibilidad, estimación) trabaja sobre un modelo de usuario: una función que tú escribes. La toolbox no ve tus ecuaciones; solo llama a esa función con un vector de factores y lee lo que devuelve. Este módulo enseña ese contrato paso a paso, en espejo con la versión MATLAB (mismas secciones, mismos modelos, mismos resultados):

  1. la firma del modelo y la forma de su salida;
  2. el orden de los factores: primero los parámetros, después las condiciones iniciales;
  3. un modelo discreto (un bucle) y uno continuo (un integrador de EDO evaluado en una rejilla);
  4. cómo se declaran los rangos, los nombres de los factores y de las salidas, qué guarda la toolbox del modelo y cómo se evalúa;
  5. los errores típicos (firma, nombres de salidas, orientación, rejilla, pasos del integrador, unidades);
  6. un ejercicio: programar un SIR discreto desde cero.

El código completo de cada modelo aparece en la página tal como está en su archivo.

2. El contrato de un modelo de usuario¶

En Python un modelo de usuario es una función (en su propio archivo .py, para poder importarla desde cualquier guion) con esta firma:

def mi_modelo(pars, domain, **opt) -> np.ndarray:

Entradas

  • pars: arreglo con los factores. La posición manda: pars[0] es el factor de la fila 0 de los rangos, pars[1] el de la fila 1, etc. Convención del curso: primero los parámetros, después las condiciones iniciales.
  • domain: la rejilla de puntos donde quieres la salida. Es model.domain por defecto, o el xdata que pases a model.evaluate(pars, xdata). Como puede empezar en cualquier punto, la condición inicial vale en un t0 fijo que el modelo conoce por su cuenta.
  • **opt: opciones del modelo que no son factores; llega como argumentos con nombre lo que pongas en UserFunctionModel(..., opt={...}). Si das opt, la función debe tener dónde recibirlo (un argumento con ese nombre, o **opt).

Salida: un arreglo de NumPy de forma (n_salidas, len(domain)): una fila por salida, en el mismo orden de los nombres de salida, evaluada exactamente en los puntos de domain. Con una sola salida también vale un vector (len(domain),).

En MATLAB el contrato es sol = f(pars, domain, opt), pero domain es [t0, tf], la función devuelve sol.x (tiempos) y sol.y (salidas x tiempo) y gsua_eval interpola linealmente en los tiempos pedidos.

3. Paso 1 — un modelo discreto: la logística¶

$N(t+1) = N(t) + r\,N(t)\,(1 - N(t)/K)$, con tres factores: r, K (parámetros) y N0 (condición inicial). Un bucle avanza un paso de tiempo por iteración. Este es el archivo logistica_discreta.py completo:

In [3]:
mostrar_codigo(ruta("logistica_discreta.py"))

"""
logistica_discreta.py — crecimiento logístico en tiempo discreto (modelo de usuario).

    y = logistica_discreta(pars, domain, t0=0)

Ecuación en diferencias:  N(t+1) = N(t) + r*N(t)*(1 - N(t)/K)

Factores, en este orden (primero parámetros, después condición inicial):
    pars[0] -> r  : tasa de crecimiento por paso (adimensional)
    pars[1] -> K  : capacidad de carga (individuos)
    pars[2] -> N0 : población en t0 (individuos)

domain = la rejilla de tiempos donde se quiere la salida (model.domain o el xdata de evaluate).
t0     = el paso donde vale N0. Llega por opt={"t0": ...}; por defecto 0.

Salida: arreglo (len(domain),) con N en los puntos de domain: una sola salida.
"""
import numpy as np


def logistica_discreta(pars, domain, t0=0):
    r, K, N0 = pars
    domain = np.asarray(domain, dtype=float)

    t = np.arange(t0, int(np.ceil(domain.max())) + 1)   # un punto por paso de tiempo
    N = np.zeros(len(t))                                # 1 salida -> 1 fila
    N[0] = N0
    for k in range(len(t) - 1):
        N[k + 1] = N[k] + r * N[k] * (1 - N[k] / K)

    return np.interp(domain, t, N)                      # valores en los puntos pedidos

4. Paso 2 — declararlo ante la toolbox: rangos, nombres de factores y de salidas¶

UserFunctionModel recibe la función misma (no su nombre) y una matriz de rangos (Np, 2) con [mínimo, máximo] por fila. La fila i corresponde a pars[i] y a names[i]: las tres listas van en el mismo orden. output_names nombra las filas de la salida, también en orden. domain es la rejilla por defecto.

5. Paso 3 — evaluarlo¶

model.evaluate(pars, xdata) hace una simulación (pars con los Np factores); xdata es opcional y por defecto es model.domain. model.evaluate_batch(M) hace una por fila de M, de forma (N, Np), y devuelve (N, salidas, tiempo).

En MATLAB es al revés: par es Np x N (una columna por simulación) y la salida de gsua_eval es N x tiempo x salidas.

6. Paso 4 — un modelo continuo: el SIR¶

Un modelo continuo resuelve sus EDO dentro de la función. El patrón es:

  1. integrar con solve_ivp desde t0 (donde vale la condición inicial) hasta el último punto pedido;
  2. pedirle la solución exactamente en la rejilla con t_eval=domain;
  3. devolver sol.y, que ya viene como (estados, tiempo).

Factores: beta, gamma (parámetros), S0, I0 (condiciones iniciales). Salidas: S, I y R, en ese orden de filas. Archivo sir_continuo.py completo:

In [8]:
mostrar_codigo(ruta("sir_continuo.py"))

"""
sir_continuo.py — modelo epidémico SIR en tiempo continuo (modelo de usuario).

    y = sir_continuo(pars, domain, t0=0.0)

dS/dt = -beta*S*I
dI/dt =  beta*S*I - gamma*I
dR/dt =  gamma*I

Factores, en este orden (primero parámetros, después condiciones iniciales):
    pars[0] -> beta  : tasa de transmisión (1/(persona*día))
    pars[1] -> gamma : tasa de recuperación (1/día)
    pars[2] -> S0    : susceptibles en t0 (personas)
    pars[3] -> I0    : infectados en t0 (personas)
R(t0) = 0 no es un factor: es una constante del modelo.

domain = la rejilla de tiempos (días) donde se quiere la salida.
t0     = el día donde valen S0 e I0. Llega por opt={"t0": ...}; por defecto 0.

Salida: arreglo (3, len(domain)), filas = salidas [S; I; R].
"""
import numpy as np
from scipy.integrate import solve_ivp


def sir_continuo(pars, domain, t0=0.0):
    beta, gamma, S0, I0 = pars
    domain = np.asarray(domain, dtype=float)

    def rhs(t, y):
        S, I, R = y
        return [-beta * S * I, beta * S * I - gamma * I, gamma * I]

    # solve_ivp avanza con pasos adaptativos y desiguales. t_eval le pide la solución
    # exactamente en los puntos de domain (con su interpolante de alto orden).
    sol = solve_ivp(rhs, (t0, domain.max()), [S0, I0, 0.0],
                    t_eval=domain, rtol=1e-6, atol=1e-8)
    return sol.y                                        # (3, len(domain))

7. Fijar un factor: rango degenerado¶

Si un factor no te interesa, dale un rango con mínimo = máximo (o usa model.fix). Queda fuera del muestreo y de la estimación, pero el modelo lo sigue recibiendo en su posición: pars siempre llega completo. En Python el factor sigue en el modelo y pars lleva siempre los Np factores; design_matrix mantiene constante la columna del fijo.

En MATLAB el factor fijo desaparece de la tabla T, y par en gsua_eval lleva solo los factores libres.

In [12]:

8. Errores típicos¶

(a) Firma. En Python, UserFunctionModel llama func(pars, domain, **opt). Si das opt={"t0": 0} a una función que no tiene argumento para recibirlo, Python falla con "unexpected keyword argument". Declara t0=... o **opt. (En MATLAB el error equivalente es declarar el modelo con dos entradas: gsua_eval siempre lo llama con tres.)

In [13]:
mostrar_codigo(ruta("errores/logistica_sin_opt.py"))

"""
logistica_sin_opt.py — la logística discreta sin argumento para opt.

Solo existe para el módulo 0: si el modelo se declara con opt={"t0": 0}, UserFunctionModel
llama logistica_sin_opt(pars, domain, t0=0) y Python falla con "unexpected keyword argument".
La versión correcta es logistica_discreta (declara t0=0, o **opt).
"""
import numpy as np


def logistica_sin_opt(pars, domain):
    r, K, N0 = pars
    domain = np.asarray(domain, dtype=float)
    t = np.arange(0, int(np.ceil(domain.max())) + 1)
    N = np.zeros(len(t))
    N[0] = N0
    for k in range(len(t) - 1):
        N[k + 1] = N[k] + r * N[k] * (1 - N[k] / K)
    return np.interp(domain, t, N)

(b) Los nombres de salida no coinciden con las filas. Los nombres de salida no reordenan nada: solo nombran las filas, en orden. Si declaras una sola salida llamada "I" para un modelo cuya fila 0 es S, la toolbox analiza S con la etiqueta "I" y no da ningún error.

(c) Orientación. La convención es salidas x tiempo. En MATLAB, desde la versión 1.13, si devuelves tiempo x salidas la toolbox lo transpone; en Python nadie la corrige: set_output selecciona filas y te entrega un instante de tiempo en lugar de una salida. No dependas de la corrección: devuelve la salida bien orientada.

(d) La rejilla de evaluación y t0. La condición inicial pertenece a un t0 fijo, no al primer punto que pidas. En MATLAB t0 = domain(1) queda fijado en T: puedes pedir xdata desde el día 20 sin problema, pero los puntos fuera de [t0, tf] salen NaN porque no hay simulación ahí. En Python no hay NaN (el modelo integra hasta donde le pidas), y el riesgo es el contrario: integrar desde domain[0], que hace "arrancar" la epidemia en el primer punto pedido.

In [18]:

"""
sir_arranca_en_domain0.py — el SIR continuo integrando desde domain[0].

Solo existe para el módulo 0: funciona mientras la rejilla empiece en 0, pero si se pide
xdata desde el día 20 la epidemia "arranca" el día 20 con I0 infectados. La condición
inicial pertenece a un t0 fijo, no al primer punto pedido.
"""
import numpy as np
from scipy.integrate import solve_ivp


def sir_arranca_en_domain0(pars, domain):
    beta, gamma, S0, I0 = pars
    domain = np.asarray(domain, dtype=float)
    rhs = lambda t, y: [-beta * y[0] * y[1], beta * y[0] * y[1] - gamma * y[1], gamma * y[1]]
    return solve_ivp(rhs, (domain[0], domain[-1]), [S0, I0, 0.0], t_eval=domain,
                     rtol=1e-6, atol=1e-8).y      # MAL: t0 = domain[0]

(e) Devolver los pasos del integrador. Sin t_eval, solve_ivp devuelve sus pasos adaptativos (pocos y desiguales) y la salida ya no tiene len(domain) columnas; la tentación es interpolar linealmente entre ellos, que es justo lo que hace gsua_eval en MATLAB con la estructura cruda de ode45. Este modelo lo hace así:

In [20]:
mostrar_codigo(ruta("errores/sir_continuo_crudo.py"))

"""
sir_continuo_crudo.py — el mismo SIR que sir_continuo, pero con los pasos del integrador.

Solo existe para comparar en el módulo 0: solve_ivp sin t_eval devuelve sus pasos adaptativos
(pocos y desiguales, con tolerancias por defecto) y aquí se interpola linealmente entre ellos,
igual que hace gsua_eval en MATLAB con la estructura cruda de ode45.
"""
import numpy as np
from scipy.integrate import solve_ivp


def pasos_del_integrador(pars, tf, t0=0.0):
    """Los tiempos y estados que solve_ivp calcula por su cuenta (sin t_eval)."""
    beta, gamma, S0, I0 = pars
    rhs = lambda t, y: [-beta * y[0] * y[1], beta * y[0] * y[1] - gamma * y[1], gamma * y[1]]
    sol = solve_ivp(rhs, (t0, tf), [S0, I0, 0.0])                     # tolerancias por defecto
    return sol.t, sol.y


def sir_continuo_crudo(pars, domain, t0=0.0):
    domain = np.asarray(domain, dtype=float)
    t, y = pasos_del_integrador(pars, domain.max(), t0)
    return np.vstack([np.interp(domain, t, fila) for fila in y])   # interpolación lineal

Con un paso de un día, el SIR discreto es

$$S_{t+1} = S_t - \beta S_t I_t,\quad I_{t+1} = I_t + \beta S_t I_t - \gamma I_t,\quad R_{t+1} = R_t + \gamma I_t.$$

"""
sir_discreto_plantilla.py — ejercicio del módulo 0: un SIR en tiempo discreto.

Copia este archivo como mi_sir_discreto.py y completa el TODO.

Con un paso de un día, el SIR discreto es:
    S(t+1) = S(t) - beta*S(t)*I(t)
    I(t+1) = I(t) + beta*S(t)*I(t) - gamma*I(t)
    R(t+1) = R(t) + gamma*I(t)

Factores (primero parámetros, después condiciones iniciales):
    pars[0] -> beta  (1/(persona*día))
    pars[1] -> gamma (1/día)
    pars[2] -> S0    (personas)
    pars[3] -> I0    (personas)
R0 = 0 al inicio, en el día t0.

Salida: arreglo (3, len(domain)) = [S; I; R] en los días de domain.
"""
import numpy as np


def sir_discreto_plantilla(pars, domain, t0=0):
    beta, gamma, S0, I0 = pars
    domain = np.asarray(domain, dtype=float)

    dias = np.arange(t0, int(np.ceil(domain.max())) + 1)   # t0, t0+1, ..., último día pedido
    Y = np.zeros((3, len(dias)))                            # 3 salidas -> 3 filas
    Y[:, 0] = [S0, I0, 0.0]

    for k in range(len(dias) - 1):
        S, I, R = Y[:, k]
        # TODO: escribe aquí las tres ecuaciones de actualización.
        #       Mientras tanto la plantilla deja S, I y R constantes.
        Y[:, k + 1] = [S, I, R]

    # Devolver exactamente los puntos pedidos (interpolación lineal entre días)
    return np.vstack([np.interp(domain, dias, fila) for fila in Y])

11. Resumen: lista de chequeo¶

  • Función en su propio archivo .py: func(pars, domain, **opt), con argumento para cada clave de opt.
  • pars[i] = fila i de los rangos = names[i]: parámetros primero, condiciones iniciales después.
  • Salida (n_salidas, len(domain)) evaluada en los puntos de domain, filas en el orden de output_names; la condición inicial vale en un t0 fijo.
  • Discreto: un bucle de t0 al último punto pedido. Continuo: solve_ivp(..., t_eval=domain) desde t0.
  • UserFunctionModel(func, names, range, domain, output_names, opt=...) crea el modelo.
  • model.evaluate_batch(M, xdata) con M de N x Np devuelve N x salidas x len(xdata).
  • Una sola salida: model.set_output("I"). Un factor fijo: rango [v, v] o model.fix("I0").
